# AlphaPilot

국내 주식(코스피·코스닥) 자동매매를 한 사람이 지켜보고 승인하고 멈추는 웹앱이다. 매일 장이 끝나면 기법 조건을 통과한 종목을 위원회(AI 또는 규칙)가 심의하고, 리스크 점검이 수량을 줄이거나 막은 뒤, 다음 거래일 주문 계획을 만든다.

## 지금 되는 것과 안 되는 것

| 되는 것 | 안 되는 것 |
|---|---|
| 지난 일봉으로 가상 계좌를 굴리는 **시뮬레이션**(하루씩 또는 여러 날 이어서) | 키움 **모의투자·실전 주문 실행**. 화면의 환경 전환은 막혀 있다 |
| 기법 7종 스크리닝, 시장 국면, 규칙 위원회, 리스크 점검, 손절·익절 | 장중 실시간 시세 감시(일봉 단위로만 판단한다) |
| 백테스트(코스피 대비, 낙폭, 월별 수익률) | 재무 데이터(키움 연결 뒤 받아온다) |
| 로그인(비밀번호 + 인증 앱), 재인증, 위변조 검사가 되는 장부 | 알림(텔레그램 등) |
| 키움 연결 확인(토큰 발급 + 잔고 읽기) 코드 | 그 코드를 실제 키움 서버에 붙여 본 적은 없다 |

AI 위원회 코드는 있지만 실제 Claude API로 호출해 본 적이 없다(가짜 클라이언트 테스트만 통과). 키를 넣고 처음 돌릴 때는 자동화 단계를 "모두 승인"으로 두고 결과를 직접 확인하기를 권한다.

**백테스트는 조정하지 않은 측정값이다.** 143종목, 2024-08-09~2026-11-13 기준으로 기본 규칙은 +19.3%(최대 낙폭 −10.5%), 같은 기간 코스피는 +104.4%(최대 낙폭 −44.9%)였다. 지금 상장된 종목만으로 돌린 결과라 실제는 이보다 나쁠 수 있다.

## 내 PC에서 실행

필요한 것: Python 3.13과 [uv](https://docs.astral.sh/uv/), Node 22 이상.

```bash
cd backend && uv sync
```

```bash
cd backend && uv run uvicorn app.main:app --port 8000
```

다른 터미널에서:

```bash
cd frontend && npm install && npm run dev
```

브라우저에서 http://localhost:5173 을 연다. 처음에는 비밀번호(12자 이상)와 인증 앱(Google Authenticator 등)을 등록한다.

처음 써 보는 순서:
1. 설정 → 시세 데이터 → **일봉 갱신**(처음 한 번, 몇 분 걸린다. 네이버 금융의 공개 일봉을 받는다).
2. 자동매매 → 판단 주체를 **규칙 위원회**로(AI 키가 없으면 AI 위원회는 새 매수를 모두 보류한다).
3. 자동매매 → 시뮬레이션 진행 → **처음부터 다시**에서 시작일을 몇 달 전으로 정한다.
4. 위쪽 **엔진 켜기** → **여러 날 이어서** 재생.
5. 관제 화면에서 통장정리와 승인 카드를 본다.

데이터는 `backend/data/alphapilot.db`(SQLite)에 쌓인다. 환경 설정은 [.env.example](.env.example)을 `.env`로 복사해서 채운다.

## 판단 주체 세 가지

자동매매 화면에서 고른다.

| 판단 주체 | 누가 결론을 내나 | Claude 호출 |
|---|---|---|
| AI 위원회 | 후보·보유 종목마다 Claude가 토론해 결론을 낸다 | 종목당 1~6회 |
| 규칙 위원회 | 좌석 의견의 가중 평균 | 없음 |
| 규칙 + AI 분기 | 규칙이 결론을 내고, 애매한 분기만 Claude에게 묻는다 | 분기당 1회 |

**규칙 + AI 분기**(`backend/app/committee/escalation.py`)는 세 단계로 움직인다.

1. 인지: 규칙 결론이 아래에 해당하면 분기로 본다.
   - 좌석 종합이 매수 기준(+0.25)이나 매도 기준(−0.25)에서 0.08 안쪽이다.
   - 규칙은 매수인데 약세 좌석이 2개 이상이거나 리스크 좌석이 음수다.
   - 보유 종목이 −4% 이하 손실인데 청산 규칙은 아직 충족되지 않았다.
2. 질문: 분석 리포트, 규칙 결론, 묻는 이유를 Claude에게 주고 허용 행동(매수·보류 또는 매도·보유) 중에서 고르게 한다.
3. 반영: 위험을 줄이는 답(매수→보류, 보유→매도, 수량 축소, 손절 좁힘)은 그대로 따른다. 위험을 늘리는 답(보류→매수, 매도→보유)은 Claude의 확신이 "보통" 이상일 때만 따른다. 답을 받지 못하면 규칙 결론을 쓴다.

리스크 좌석 거부권과 약세장 매수 금지는 Claude에게 묻지 않는다. 어떤 결론이든 리스크 점검을 다시 통과해야 한다. 견본 데이터 110거래일에서는 판단 102건 중 35건이 분기였다(Claude는 가짜 클라이언트로 대신했다).

## 내 종목 운용(바구니)

자동매매 → **내 종목 운용** 탭. 총 투입 금액을 바구니로 나누고(예: 100만 원 → 중장기 50만, ETF 50만), 바구니마다 종목(국내주식·국내 상장 ETF), 운용 지침(위원회에 주는 프롬프트), 판단 주체, 심의 주기, 나눠 살 횟수, 방식(가상 운용·알림만)을 정한다.

- 바구니마다 위원회가 동시에 심의해 종목별로 더 모으기·모으기·쉬기·줄이기·팔기 중 하나를 낸다. 가상 운용은 다음 거래일 시가에 가상으로 체결하고, 알림만은 권장 수량만 보여 준다.
- 계획을 저장할 때마다 새 판(r1, r2, …)이 생기고, 바뀐 점과 그 판 기간의 성과가 남는다. 예전 판으로 되돌리면 그 내용으로 새 판을 만든다.
- 같은 종목·주기·금액으로 "규칙만"과 "단순 적립" 기준선을 늘 함께 계산하고, 과거 시작일부터 두 기준선을 돌려 볼 수 있다. AI 판단은 과거로 돌리지 않는다.
- 설계와 규칙: [docs/sleeves.md](docs/sleeves.md). 미국주식 직접 매매와 키움 실주문은 아직 없다.

## 데모 사이트(GitHub Pages)

https://shchocho.github.io/alphapilot/ 는 서버 없이 화면만 보여주는 **읽기 전용 데모**다. 시뮬레이션을 한 번 돌려 저장한 응답을 읽기만 하고, 엔진 조작·설정 변경 같은 동작은 막혀 있다. 데모를 새로 만들려면:

```bash
cd backend && uv run python scripts/export_demo.py 2026-07-01
```

```bash
cd frontend && npm run build:demo
```

그다음 `frontend/dist-demo`를 `gh-pages` 브랜치에 올린다.

평일 18:10(KST)에는 `.github/workflows/demo.yml`이 이 세 단계를 자동으로 돌린다. 그래서 첫 화면 3D 장면의 수(살펴본 종목 → 기법 조건 통과 → 위원회 심의 → 주문 계획)는 최신 거래일 것으로 바뀐다. 내보내기가 `frontend/src/features/landing/funnel.latest.json`에 그날의 수를 적고 데모 빌드가 그 파일을 읽는다. 파일이 없거나 데모 빌드가 아니면 2026-10-02 표본이 보인다. 자동 실행은 `gh-pages`를 빌드 결과 커밋 하나로 덮어쓴다.

## 안전장치

- 실전 전환은 서버 환경변수 `ALLOW_LIVE_TRADING=true`, 키움 키, 인증 코드 재입력, 확인 문구가 모두 있어야 하고, 지금은 그와 별개로 주문 실행기가 없어 막혀 있다.
- AI가 답하지 못하거나, 형식에 맞지 않게 답하거나, 하루 예산을 넘으면 그 건은 사지 않는다.
- 리스크 점검은 수량을 줄이거나 거부할 수만 있다. 늘리지 못한다.
- 손절·익절·기간 만료 청산은 AI를 거치지 않는 규칙이다.
- 서버가 다시 시작되면 사용자가 확인할 때까지 모든 주문 계획이 승인을 기다린다.
- 하루 −2%, 한 주 −5%, 한 달 −8%, 고점 대비 −20%에서 단계적으로 새 매수를 멈추거나 엔진을 정지한다(설정에서 바꿀 수 있고, 느슨하게 바꿀 때는 인증 코드를 다시 묻는다).

## 책임

투자 판단과 그 결과는 사용하는 사람의 것이다. 이 프로그램은 수익을 보장하지 않으며, 실전에 쓰기 전에 시뮬레이션과 모의투자로 충분히 확인해야 한다.
