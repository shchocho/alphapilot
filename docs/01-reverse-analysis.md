## 1. 멀티에이전트 매매 저장소

원자료: `research/01-multi-agent-repos.md` (2,731줄, `경로:줄` 인용). 대상: ai-hedge-fund v1(태그 v2026.7.10)과 v2(HEAD v2.7.2), TradingAgents v0.7.1, FinRobot(README).

**가장 중요한 발견** [소스 확인]: ai-hedge-fund는 최신판(v2)에서 **"LLM은 주문에 손대지 않는다"** 원칙의 결정론 엔진으로 전면 재작성됐다. 신호 혼합(`blend_signals`) → 7단계 축소 전용 클램프 → 목표 재검증 → 해시 연결 원장, 비용 모델, 킬 스위치, 실패 시 자동 정지, 승인 모달을 갖췄다. v1에서 드러난 문제(LLM이 결정론 신호를 검증 없이 덮어씀, JSON 파싱 실패가 '강세 확신 0'으로 바뀜, 같은 종가에 결정·체결, 비용 0, 재무 룩어헤드)를 고친 결과다.

| 구조 | ai-hedge-fund v1 | ai-hedge-fund v2 | TradingAgents |
|---|---|---|---|
| 판단 주체 | 페르소나 12 + 분석 4 → PM(LLM) | 결정론 좌석 + 혼합 | LLM 토론 사슬(애널리스트 4 → 강세·약세 → 리서치 매니저 → 트레이더 → 리스크 3 → PM) |
| LLM 역할 | 최종 행동·수량 선택(사후 검증 없음) | 주문 경로 밖(서술) | 전부 |
| 리스크 | 변동성·상관 배수로 종목 한도 | 축소 전용 7단계 클램프 | LLM 리스크 토론 |
| 백테스트 | 같은 종가 체결, 비용 0 | T+1 종가 체결, 비용 반영 | 시점 방어 강함(날짜 주입·제출일 재무) |
| 기록 | 없음 | 해시 체인 원장 | 반성문 메모리(5거래일 뒤 정산) |

**사용자 결정과의 관계**: 사용자는 "AI가 최종 판단까지"를 골랐다. 그래서 v2처럼 LLM을 주문 경로에서 빼지는 않되, v2의 안전장치를 그대로 둘러싼다.
1. AI가 고를 수 있는 행동과 최대 수량은 **규칙이 먼저 계산**한다(v1 PM의 좋은 부분). AI는 그 범위 안에서만 고른다.
2. AI 결론은 **축소 전용 게이트**를 거친다. 게이트는 줄이거나 거부할 수 있고 늘릴 수 없다(v2 클램프).
3. AI 응답이 스키마에 맞지 않거나, 거절·시간 초과·예산 초과면 결론은 **보류(HOLD)** 다. 절대 '강세'로 바꾸지 않는다(v1 결함의 반대).
4. 좌석(관점) 계약은 v2 `Signal`을 확장한다: 값 [−1, 1], 확신, 기권 여부, 기간, 구성 요소, 최대점(규칙에서 자동 합산), 입력 데이터의 기준 시각, 규칙 버전. 데이터가 없으면 기권.
5. 장 마감 뒤 결정, 다음 거래일 체결. 백테스트도 같은 규칙.
6. 기준 시각(as_of)을 밖에서 주입하고, 과거 실행에서 "현재값" 데이터는 거부한다(TradingAgents의 시점 방어).
7. 강세·약세·판정 토론과 5단계 등급, 판독 실패 시 "검토 필요" 상태(TradingAgents). 결정이 바뀐 종목만 다시 심의해 비용을 줄인다.
8. 좌석 이름은 실존 투자자 이름 대신 관점 이름(가치·성장·추세 …)으로 쓰고, 프롬프트 문구는 새로 쓴다(라이선스·사칭 위험).

**미국 임계값을 그대로 쓰지 않는다**: v1의 ROE > 15%, P/E < 15 같은 절대 기준은 한국 시장 분포와 다르다. PER·PBR·ROE는 업종 안 백분위로 바꾼다.

라이선스: ai-hedge-fund MIT, TradingAgents Apache-2.0, FinRobot Apache-2.0(이름 사용 불가). 코드·프롬프트는 옮기지 않고 구조만 참고한다.

## 3. 키움 REST API

원자료: `research/03-kiwoom-rest-api.md` (공식 포털 가이드·공지·FAQ, 키움증권 공식 GitHub 런타임·플러그인 주석까지 교차 확인, 사실마다 [확인됨]/[불확실] 표기)

**설계를 바꾼 사실**
| 사실 | 설계 반영 |
|---|---|
| IP 등록 필수(최대 10개), 토큰이 발급 IP에 묶임(다른 IP면 8010) | 클라우드 서버는 고정 출구 IP 하나. 설정 화면에 공인 IP 표시·등록 안내 |
| 토큰 24시간, 6시간 뒤 재발급하면 기존 토큰 폐기 | 토큰 발급 주체는 엔진 프로세스 하나. 개발용 스크립트가 같은 키로 토큰을 받지 않게 문서화 |
| 계좌 TR(kt00001·kt00004·kt00018 등) **초당 1회**(2026-11-12부터), 모의는 TR당 초당 1회 | `(토큰, api-id)`별 토큰 버킷, 계좌 조회는 캐시·이벤트(실시간 04 잔고) 위주 |
| 업무 오류도 HTTP 200 + `return_code`, 유량 초과는 429 | 오류 분류기(입력·유량·토큰·단말·모드 불일치·모의 미지원) |
| 주문 결과가 애매할 수 있음, 정정·취소도 새 주문번호 | 주문 자동 재시도 금지, 미체결·주문체결내역으로 대사 |
| WebSocket 계좌당 1세션, PING 에코 필수, 무음 정지 실측 사례 | 워치독(무수신 180초) + 재접속 시 재등록 + REST 재동기화 |
| 모의투자는 KRX만, NXT·SOR 불가 | 1차 범위 KRX 고정 |
| 2026-09-14 제도 변경: KRX 애프터마켓(16:00~20:00) 신설, 시간외단일가 TR·주문유형 62 삭제 | 정규장 전용 일봉(ka11081)으로 지표 계산, 애프터마켓은 후속 단계 |
| 서버 점검 단절 월~토 07:50~07:55 | 08:00 작업에 재시도 여유 |
| 시세는 본인 투자 목적 전용, 재배포 금지 | 1인 전용 서비스 유지 |
| 3개월 실전 도메인 미사용 시 자동 해지(모의만 쓰면 미사용) | 연결 카드에 "장기 미사용 해지 위험" 상태 표시 |
| 가격 부호 = 전일 대비 방향, 0-패딩·이중부호·2³²−1 포화·단위 혼재 | 공통 파서(`kw_num`, `kw_price`, `kw_volume`)와 TR별 단위표 |
| 조건검색: 영웅문4에서 저장한 조건식만 사용, 세션당 실시간 10건·조건당 100종목 | 유니버스 공급원으로 선택 연결 |

**검증이 남은 것**: 토큰 재발급 실제 동작, WebSocket 정식 경로, 유량 초과 본문, 실시간 주문체결 상태 전이 순서 등 17개(원자료 §19). 키를 받은 뒤 모의 도메인에서 확인한다.

## 4. UX 레퍼런스

원자료: `research/04-ux-references.md` (토스증권, 키움 영웅문 조건검색·감시주문, 젠포트·퀀터스, TradingView, Robinhood, 3Commas·Composer·Alpaca·Option Alpha, QuantConnect, 사고 사례·규제 자료)

**핵심 결론**
1. 기존 서비스는 가격·자산을 가장 크게 보여준다. 기계가 주문하는 앱에선 "지금 개입해야 하나"가 먼저다 → 모든 화면 상단 상태 바, 관제 첫 줄은 경고·승인 대기·일 손실 한도 사용률.
2. 정지는 세 가지(일시정지 / 정지 / 전량 매도 후 정지)로 나누고 결과로 이름 짓는다(QuantConnect, Cryptohopper, Upstox).
3. 자동화는 단계(0 알림 → 1 모두 승인 → 2 한도 안 자동 → 3 완전 자동)로 열고 기본값은 승인(키움 StopLoss 자동주문 별도 동의, TradersPost, 퀀터스).
4. 판단 근거는 "왜 샀나"와 "왜 안 샀나"를 모두 남긴다(Option Alpha 필터 탈락 로그, TradingAgents 찬반 토론, Danelfin 신호 분해).
5. 백테스트는 가정을 먼저, 지수와 나란히, 자산 곡선과 낙폭을 같은 시간축에, 표본 수 경고와 함께(Composer, TradingView, QuantConnect, 퀀터스).
6. 가격 색(빨강·파랑)과 위험·모드 색을 토큰 단계에서 분리한다.
7. 축하 연출·배지·랭킹·수익 인증 푸시를 두지 않는다(영국 FCA 실험: 푸시와 보상만으로 거래 빈도·위험 투자 증가, 국내 비판 사례).

17개 설계 원칙과 화면별 권장 구성은 원자료 §4~5에 있고, SPEC §3.7에 반영했다.

## 5. 토스증권 직접 분석에서 가져갈 것

1. **비교 기준을 문장으로**: "어제보다 +1,200원 (+0.6%)". 등락 숫자만 던지지 않는다.
2. **기법을 프리셋 스크린으로**: 쉬운 이름 + 한 줄 설명 + 적용 조건 칩. 우리 "종목 발굴"의 기본 형태.
3. **항상 보이는 시장 맥락**: 토스는 하단 티커에 지수를 둔다. 우리는 엔진 상태·모드·장 운영 상태·시장 국면을 상단 상태 바에 고정한다(자동매매에선 엔진 상태가 지수보다 중요).
4. **목록-미리보기**: 표에서 행을 고르면 옆에서 차트를 미리 본다. 페이지 이동을 줄인다.
5. **주문 패널의 비율 버튼과 총액 미리보기**: 승인·수동 주문 화면에 그대로 쓴다. 매수 빨강, 매도 파랑.
6. **장식 없는 고밀도**: 얇은 구분선과 카드 여백으로 밀도를 정리한다.
