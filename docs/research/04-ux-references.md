# 04. UX 레퍼런스 역분석: 국내외 주식·자동매매·퀀트 서비스

- 작성일: 2026-11-15
- 목적: 한국 주식 자동매매 웹앱의 화면 구조와 상호작용 설계 원칙을 공개 자료로 도출한다.
- 우리 앱 화면: 자동매매 관제 대시보드, 종목 발굴(스크리너), 종목 상세(차트 + 매매 판단 근거 + 다관점 투자위원회 의견), 자동매매 설정·주문 승인, 포트폴리오(보유·주문·매매일지), 백테스트, 증권사 연결 설정
- 방법: 공식 도움말, 개발 문서, 기능 소개, 언론 보도, 리뷰처럼 공개된 자료만 읽었다. 로그인·가입·다운로드는 하지 않았다. 원문은 인용하지 않고 요약했다.
- 한계: 위키독스(젠포트 매뉴얼), 네이버 금융, IBKR 도움말 일부, Danelfin 일부 페이지는 자동 열람이 막혀 검색 요약이나 2차 자료로 보완했다. 로그인 뒤 화면(토스증권 PC 실제 화면, 3Commas 봇 화면 등)은 직접 보지 못했으므로 공개 설명 기준이다.
- 근거 표기: `[공식]` 회사 도움말·문서, `[보도]` 언론, `[2차]` 블로그·리뷰·제3자 정리, `[추론]` 자료를 바탕으로 한 우리 판단, `[관례]` 국내 증권 화면에서 통용되는 표기. 괄호 속 기호(예: K3)는 8장 출처 목록의 번호다.

## 0. 핵심 요약

1. 관제 화면에서 가장 크게 보여줄 것은 수익률이 아니라 "지금 사람이 개입해야 하는가"다. 엔진 상태, 모의/실전, 장 세션, 증권사 연결, 승인 대기, 일일 손실 한도 사용률을 모든 화면 상단에 고정한다. 키움 자동감시주문의 감시중/중지 구분, QuantConnect의 실행 통계 띠, 퀀터스의 계좌별 연결 상태가 같은 방향이다.
2. "정지"는 한 가지가 아니다. 일시정지(신규 주문만 중단), 정지(미체결 취소·보유 유지), 전량 청산 후 정지를 나누고 버튼 이름을 결과로 짓는다(QuantConnect Stop/Liquidate, Bitsgap, Cryptohopper, Upstox).
3. 자동화 수준은 단계적으로 열고 기본값은 "승인 필요"로 둔다. 근거는 키움 StopLoss의 수동/자동 주문(자동은 별도 동의), TradersPost의 Auto Submit 해제 시 검토함, 퀀터스의 "사용자 확인 대기" 상태다.
4. 판단 근거는 "왜 샀나"뿐 아니라 "왜 안 샀나"까지 남긴다. Option Alpha의 필터 탈락 로그, TradingAgents의 강세·약세 토론 구조, Danelfin의 긍정·부정 신호 분해를 합쳐 위원회 의견을 찬반, 데이터 시점, 확신 등급과 함께 보여준다.
5. 백테스트는 가정(기간·비용·슬리피지·리밸런싱·생존편향)을 먼저 보여주고, 지표는 벤치마크와 나란히, 자산곡선과 낙폭은 같은 시간축에, 학습/검증 구간은 나눠서 표시한다(Composer, TradingView, QuantConnect, 퀀터스).
6. 한국 관례(상승 빨강·하락 파랑, 억·조 단위, 호가단위, KRX·NXT 복수시장, 2026-09-14 신설 KRX 애프터마켓)를 따르되, 가격 색과 위험 색은 디자인 토큰 단계에서 분리한다.
7. 피할 것: 축하 연출, 배지, 랭킹, 수익 인증 푸시, 극단적 수익률 예시, 위험을 가리는 친근한 용어, 버튼 하나로 끝나는 "이해했어요" 동의. 영국 FCA 실험에서는 푸시 알림과 포인트·경품만으로 거래 빈도와 위험 투자 비중이 올라갔다. 국내에서는 토스증권의 옵션 광고와 용어, 카카오페이증권의 수익 인증 푸시가 비판받았다.

## 1. 서비스별 분석

### 1.1 토스증권 (모바일 MTS·PC WTS)

화면 구성과 정보 위계
- PC(WTS)는 2024-07에 나왔다. 상단 탐색에 홈, 뉴스, 주식 골라보기, 내 계좌, 검색을 둔다. 보유·관심·최근 본 종목처럼 사용자 행동과 관련된 정보는 계정 메뉴에 숨기지 않고 오른쪽 사이드 패널에 늘 보이게 했다 `[2차]` (T1).
- 2025-10 첫 대규모 개편의 키워드는 직관적인 정보, 빠른 주문, 맞춤형 인터페이스였다. 홈에 경제지표·실적 발표 일정·주요 지수·실시간 거래량 차트를 모았고, 종목 상세에서는 차트·호가·뉴스·커뮤니티를 화면 전환 없이 본다. 사이드창은 PIP로 띄워 옮길 수 있다. 현재가로 바로 주문하는 간편주문이 생겼고, 종목 상세 블록의 위치와 순서를 사용자가 바꿀 수 있다. 보조지표와 그리기 도구는 PC와 모바일이 동기화된다 `[보도]` (T2).
- 2026-06 개편에서는 전체화면 차트를 최대 4개까지 띄우고, 차트 화면에서 바로 주문·정정하며, 시세와 투자자별 수급처럼 원하는 정보를 탭으로 묶어 순서를 바꾸게 했다 `[보도]` (T3, T4).
- 모바일 종목 상세(초기 버전 리뷰): 위에 종목명과 현재가, 가운데 차트, 아래 뉴스와 재무가 있고 구매 버튼은 하단에 고정이다. 가격 영역을 누르면 바텀시트에서 지정가/시장가와 호가별 잔량을 보고, 가격과 수량은 다른 단계에서 입력한다(한 화면 한 기능). 같은 리뷰는 정보가 단순해 숙련자에게는 부족하고, 주문 처리 대기가 길어 불안했다고 지적했다 `[2차]` (T7).

정보 설계와 문구
- 토스증권은 기업에 대한 객관적 정보를 주고 고객이 스스로 매수·매도를 판단하는 투자자로 자라도록 돕는 것을 비전으로 내세운다 `[공식]` (T12). 우리 위원회 의견도 "판단 재료 정리"라는 같은 자리에 두는 편이 안전하다 `[추론]`.
- 토스의 프로덕트 원칙 10가지 중 우리 앱에 직접 쓰이는 것: 쉬운 말(Casual Concept), 단순한 정책(Simple Policy), 다음 행동이 한눈에 보이게(Clear Action), 행동의 이유 설명(Explain Why), 페이지당 핵심 메시지 하나(One Thing), 기다림 제거(No More Loading), 기능 추가는 최후 수단(Minimum Features) `[공식]` (T5).
- 투자 정보 전달: 어려운 용어는 툴팁이나 별도 콘텐츠로 풀고, 한 번 더 누르면 자세한 설명이 열리는 단계적 열람을 쓴다. 국내장·미국장 시간에 맞춰 뉴스를 바꿔 보여주고, AI가 기사를 요약해 호재·악재로 분류한다. 콘텐츠에 나온 기업의 로고에서 종목으로 바로 간다 `[공식]` (T6).
- 주식 골라보기(스크리너): 자극적인 문구 대신 기업가치·수익성·배당 같은 기준과 자주 쓰는 투자 키워드를 필터로 내놓았다 `[2차]` (T1). "저평가 성장주" 같은 태그가 미리 정한 재무 조건 묶음과 정렬 기준으로 동작한다는 사용기도 있다 `[2차]` (T13).
- UX 라이팅은 일관된 보이스톤과 오류 상황의 불쾌감 최소화를 기준으로 다듬는다 `[공식]` (T14).

경계할 사례: 쉬운 UX가 위험을 가린 경우
- 미수거래를 친근한 "외상" 표현으로 바꿔 위험을 가렸다는 지적이 나왔고, 금감원이 법령과 다른 용어가 오인을 부를 수 있다며 시정을 요구해 표현이 바뀌었다 `[보도]` (T8).
- 해외주식 옵션 사전 신청 광고가 기초자산이 몇 % 오르면 옵션은 수백 % 오른다는 식의 예시를 썼고, 모의거래 화면의 위험 고지도 부족하다는 금감원 지적을 받았다. 토스증권은 이벤트와 모의거래를 멈추고 출시를 미뤘다(2025-11) `[보도]` (T9). 비판 요지는 짧은 설명 뒤 곧바로 거래 화면으로 넘어가는 흐름, "다음" 버튼을 "이해했어요"로 바꾼 동의 방식, 극단적 수익률 강조, 게임식 문구, 지원금 강조였다 `[보도]` (T8).
- 2025-12 금감원은 키움·토스증권 해외투자 영업 현장검사와 함께 과장 광고나 불충분한 위험 설명에 강하게 조치하겠다고 밝혔다 `[보도]` (T9, T10).

우리 앱에 가져올 것과 피할 것
- 가져올 것: 오른쪽 사이드 패널 상시 노출(우리 앱에서는 승인 대기·보유·최근 이벤트), 상세 블록 재배치, 차트 위 주문·정정, 툴팁과 단계적 열람, AI 요약의 호재/악재 분류, 단순한 기본 흐름과 숙련자용 고밀도 보기를 함께 제공.
- 피할 것: 위험을 낮춰 보이게 하는 용어 치환, 버튼 문구로 동의를 대신하기, 수익 예시 중심 안내. 쉬운 말은 법정 용어를 대체하지 말고 함께 적는다.

### 1.2 키움증권 영웅문4·영웅문S#: 조건검색, StopLoss, 자동감시주문

조건검색 [0150]과 조건검색실시간 [0156] `[공식]` (K1, K2)
- 화면은 세 영역이다. 지표 목록(분류별·가나다순·검색), 조건식 편집(조합·저장), 결과(필드 설정·정렬·관심종목 저장·미니차트).
- 조건 사이를 더블클릭하면 AND/OR가 바뀌고, 범위를 드래그해 NOT과 괄호를 건다. 조건식 하나에 조건은 최대 20개다. 대상 종목군(업종·관심·보유·테마)과 봉 기준을 한꺼번에 정하고, 매수용·매도용 조건을 구분한다.
- 검색 방식은 전체검색, 결과내검색, 결과외검색, 순차검색(과거부터 시간순)이다.
- 실시간 화면은 저장한 조건을 실시간 시세에 적용해 편입 종목은 목록에 더하고 이탈 종목은 뺀다. 이탈 종목을 자동으로 지울지, "이탈삭제" 버튼으로 지울지 고른다. 소리 옵션, 새 종목이 편입되면 열린 화면을 그 종목으로 바꾸는 종목연동 옵션이 있다. 편입·이탈을 색이나 표식으로 구분한다는 설명은 없다.
- 데이터 주의 문구: 조건검색은 통합·KRX 시세 기준이고, 재무 값이 다른 화면과 다를 수 있다고 알린다.

주식 StopLoss [0621]: PC에서 도는 방식 `[공식]` (K3)
- 보유종목 스탑로스와 잔고편입 스탑로스 탭, 거래소(통합·KRX·NXT) 선택이 있다. 종목 정보 탭은 잔고, 미체결, 10단 호가, 차트, 조건요약, 사용자조건으로 구성된다.
- 조건 종류: 이익실현, 이익보존(이익실현과 함께만), 손실제한, 트레일링스탑(목표가 도달 뒤 고가 대비 하락 감시). 단위는 틱·%·원, 감시 기준가는 매입단가·직접 입력·감시 시작 시점 현재가 중에서 고른다.
- 조건요약 탭이 %·틱으로 입력한 값을 실제 호가 가격으로 바꿔 보여준다. 호가단위에 맞게 자동 보정하는데, 이익 쪽은 윗 호가로 올리고 손실 쪽은 아래 호가로 내린다.
- 주문 방식은 수동(확인창을 거쳐 주문)과 자동(즉시 주문)이고, 자동은 별도 동의가 필요하다. 주문 가격 기준은 주문 시점 현재가와 조건을 만족한 시점 가격 중에서 고른다.
- 상태 표시: 감시 중인 조건은 컬러, 중지된 조건은 회색 가상 조건으로 그린다. 차트에 감시 가격을 가로선으로 그려 현재가와의 거리를 보여준다. 트레일링 단계 아이콘은 흑백에서 컬러로 바뀌며 진행 단계를 알린다. 전체 상태를 문장으로 알려주고, ▶ 버튼으로 개별·전체 감시를 시작하거나 멈춘다.
- 안전장치: HTS를 끄면 감시가 멈춘다. 재접속하면 자동 주문 조건이 수동 주문으로 바뀐다. 감시를 시작하는 순간 이미 만족한 조건은 바로 주문될 수 있다고 경고하고, 실시간 시세가 변할 때만 감시하는 옵션을 준다. 시세 급변이나 빈 호가에서는 설정보다 불리한 가격에 체결될 수 있다고 알린다. 수량과 가격이 들어간 주문창에서 Enter·Space 키로 주문이 나갈 수 있으니 이 기능을 끄라고 안내한다.

주식 자동감시주문 [0624]: 서버가 감시하는 방식 `[공식]` (K4)
- 탭: 보유종목 자동매도, 신규종목 자동매수, 잔고편입 자동매도. 간편설정과 일반설정을 전환한다.
- 쓰기 전에 이용 동의, 유의사항 확인, 비상연락처 등록을 거친다.
- 조건 추가와 감시 시작을 나눴다. 조건을 추가해도 감시시작을 눌러야 돈다. 감시내역 목록에서 개별·전체 시작·중지·삭제를 하고, 목록 위에 중지 상태와 건수를 알린다.
- 한도와 수명: 보유 자동매도 50건, 신규 자동매수 50건, 잔고편입 5건, 유효기간은 최대 90일이다. 주문이 실행되거나 잔고가 0이 되거나 시스템 오류가 나면 감시가 자동으로 지워진다. 시스템 장애나 시세 오류로 강제 중지하면 비상 SMS로 알린다.
- 감시 가능 시간은 거래소와 세션마다 다르고, 시장가 주문은 정규장에서만 된다. 사용자 ID 하나당 단말기 한 대에서만 쓴다.

적립식 자동주문 `[공식]` (K5)
- 흐름은 서비스 안내 → 약정 등록 → 종목 등록·변경·해지 → 주문처리내역 조회다. 매수 주기(매일·매주·매월)와 주문 유형(장 시작 전·마감 전 동시호가, 최유리지정가)을 고른다. 이 서비스는 2026-06-18 종료가 공지되었고, 대안으로 영웅문S#의 "주식더모으기"를 안내한다.

우리 앱 시사점
- 그대로 가져올 것: 감시중/중지의 색과 형태 구분, 차트 위 감시 가격선, 설정값의 실제 가격 환산 미리보기, 호가단위 자동 보정과 보정 방향 표시, "조건 추가"와 "가동" 분리, 자동 주문의 별도 동의, 재접속 후 수동(승인) 모드로 돌아가기, 강제 중지 시 다른 채널로 통보, 건수와 유효기간 상한.
- 보완할 것: 실시간 편입/이탈을 눈에 띄게 구분하기(키움 문서에는 없음), Enter 주문 같은 실수 경로 없애기, "앱을 꺼도 계속 도는가"를 화면에 분명히 적기(키움은 0621과 0624의 동작이 다르다).

### 1.4 국내 퀀트·자동매매 서비스

젠포트 (뉴지스탁) `[공식]` (Q1)

퀀터스 (Quantus) `[공식]` (Q3–Q5)

- 실행: 사용자가 정한 조건·주기로 실행하고, TWAP·VWAP 분할 집행을 지원한다. 주문 예약 카드에 "사용자 확인 대기" 상태가 있고, 대화로 내는 주문은 실행 전에 확인을 받는다.
- 실전투자 대시보드: 총자산, 총수익률, 일간 수익률, 전략별 배분과 미운용 예수금, 누적수익률 차트, 계좌별 카드(증권사·전략·금액·연결됨/대기). 모의계좌에는 라벨이 붙는다.

- 신뢰 장치: "집계 기준" 페이지에서 공개 숫자의 정의를 밝힌다. 등록 계정 수는 활성 이용자 수가 아니고, 백테스트 요청 수에는 실패와 재시도가 들어가며, 거래대금은 실계좌만 세고 모의계좌는 뺀다. 백테스트는 미래 수익을 보장하지 않는다는 한계를 해석할 때 함께 적용하라고 적는다. 투자자문이 아니고, 자산은 고객 명의 계좌에 그대로 있으며 서비스는 주문만 전달한다고 밝힌다.

인텔리퀀트 iQ 스튜디오: 듀얼 모멘텀·올웨더 같은 템플릿 전략을 코드 없이 백테스트하고 수익률·MDD·샤프를 본다 `[2차]` (Q6).

### 1.5 TradingView: 스크리너, 전략 테스터, 알림

스크리너 `[공식]` (TV3–TV6)
- 결과 표 위에 적용 중인 필터를 나열하고, "+"로 필터를 검색해 더한다. 필터 이름 옆 물음표 아이콘이 그 지표의 설명 문서로 연결된다.
- 인기 스크린(프리셋), 흔한 신호의 기본값, 지표 길이·주기·조건을 바꾸는 사용자 값이 있다. 표 위 탭으로 손익계산서·재무상태·현금흐름·밸류에이션 같은 열 세트를 바꾸고, 열마다 이동·정렬 메뉴가 있다. 자동 새로고침, 관심목록 추가, 내보내기를 지원한다.
- 사용자 스크린은 활성·비활성 필터, 열 세트, 정렬, 보기 방식을 저장한다. 자동 저장은 기본으로 꺼져 있다.
- AI 스크리너(공개 베타)는 자연어 설명을 필터와 열로 바꾸는데, 실행하면 기존 필터·열·정렬을 덮어쓴다.

전략 리포트 `[공식]` (TV1, TV2)
- 차트 아래 패널이고, 탭은 Metrics → 성과 분석 → 거래 분석 → 거래 목록 순서다. 전략을 붙이면 Metrics 탭이 먼저 열리고 총손익, 최대 낙폭, 승률, 손익비 같은 핵심 지표와 자산곡선이 나온다. 바이앤홀드 곡선을 켜서 비교한다.
- 성과 분석에는 구성별·기간별·벤치마크·증거금·성장과 하락 분석, 거래 분석에는 손익 분포·연속 승패·진입 시간대 분석이 있다. 성과 지표는 전체·매수·매도로 나눠 보여준다.
- 거래 목록 열: 거래 번호, 유형, 시각, 신호, 가격, 수량, 순손익, 누적 손익, 런업, 낙폭.
- 속성에서 체결 현실성(봉 내부 세분화, 지정가 체결 방식, 주문 체결 지연)을 조정한다.

알림 `[공식]` (TV7)
- 활성 알림 탭과 이미 발동한 알림 로그 탭을 나눈다. 알림에는 만료가 있고 최장 두 달이다.
- 외부 자동매매로 웹훅을 보낼 때, 알림 로그에는 있는데 하위 시스템에 주문이 없으면 웹훅 연결 문제라는 진단 안내가 있다 `[2차]` (TV8). 우리 앱도 "신호는 났는데 주문이 없다"를 원인별로 보여줘야 한다 `[추론]`.

### 1.6 Robinhood·Webull: 단순화의 형식과 대가

- 주문은 검토 화면을 거친 뒤 위로 밀어 제출하는 제스처로 끝난다. 일부 상품에는 검토 화면을 건너뛰는 자동 전송 옵션이 있다 `[공식]` (R6, R7). 화면낭독기 사용자가 이 제스처에 어려움을 겪었다는 보고가 있어, 제스처 확인에는 대체 수단이 필요하다 `[2차]` (R8).
- Robinhood Legend(데스크톱): 템플릿에서 시작해 위젯을 더하고, 크기를 바꾸고, 옮긴다. 레이아웃은 최대 8개다. 같은 색 그룹으로 묶은 위젯끼리 종목을 공유해서, 관심목록에서 종목을 누르면 차트·주문·포지션 위젯이 따라 바뀐다 `[공식]` (R4, R5).

## 2. 한국 사용자 관례와 시장 구조

### 2.1 색과 기호
- 상승 빨강, 하락 파랑, 보합 회색이 표준이다 `[관례]`. 미국식(상승 초록)과 반대라서 해외 차트 라이브러리 기본값을 그대로 쓰면 안 된다. 손익도 같은 규칙을 쓴다(이익 빨강, 손실 파랑).
- 색에만 기대지 않도록 기호를 함께 쓴다. ▲/▼(상승/하락), 상한가·하한가는 별도 표식(↑/↓ 또는 "상한"/"하한" 배지)이 관례다 `[관례]`.
- 충돌 주의: 일반 UI에서 빨강은 오류·위험인데 한국 시세에서는 상승이다. 위험, 오류, 실전 모드 표시는 가격 빨강과 다른 토큰으로 정의하고 아이콘, 문구, 형태(배너·테두리)를 반드시 함께 쓴다 `[추론]`. 색만으로 의미를 전하지 말라는 접근성 원칙과도 맞는다 (G7).

### 2.2 숫자와 단위 (권장 규칙) `[관례+추론]`
- 가격: 원 단위 정수, 천 단위 쉼표. 해외 주식은 달러 소수 둘째 자리.
- 전일 대비: 등락폭과 등락률을 함께, 부호는 항상 붙인다. 예: `▲1,200 (+1.52%)`, `▼350 (−0.84%)`, 보합 `0 (0.00%)`.
- 용어: 등락률(전일 종가 대비)과 수익률(내 매입가 대비)을 섞지 않는다.
- 큰 금액: 시가총액은 조·억(예: 1조 2,345억원), 거래대금은 억원. 표에서는 단위를 열 머리글에 두고 숫자는 오른쪽 정렬, 고정폭 숫자 글꼴을 쓴다. 줄여 쓴 값은 툴팁에 정확한 값을 준다.
- 거래량은 주. 시각은 KST 24시간제, 로그는 초 단위까지.
- 문체는 한 가지로 통일한다(예: 해요체). 오류 문구는 원인과 다음 행동을 적는다 (T14).

## 3. 교차 분석: 자동매매에만 있는 UX

### 3.1 상태 가시성
- 관찰: 키움(감시중 컬러/중지 회색, 전체 중지 상태와 건수 안내), 젠포트(배치 중/완료, 마켓타이밍), 퀀터스(계좌별 연결됨/대기), QuantConnect(실행 통계 띠, 차트 위 배포·정지·오류 표식, 조직 전체 라이브 대시보드).
- 정리: 사용자가 늘 알아야 할 상태는 일곱 가지다. 엔진(가동/일시정지/정지/오류), 모드(모의/실전), 시장 세션, 증권사 연결과 토큰, 데이터 신선도(마지막 시세 수신 시각), 한도 사용률, 승인 대기. 모두 텍스트, 아이콘, 색을 함께 써서 어느 화면에서나 보이게 한다.

### 3.2 모의/실전 구분
- 관찰: Alpaca, 한국투자증권 KIS, 키움 REST 모두 모의와 실전의 호스트와 키가 다르다 (A4, B9, K6, K7). 키움은 실전 키로 모의 도메인에 접속하면 오류를 낸다 (K7). 한 프로세스 안에서 모드를 토글하면 실전과 모의가 섞일 위험이 있다는 개발자 경고도 있다 `[2차]` (B9). NN/g는 실수하면 큰일 나는 모드는 피하고, 꼭 써야 하면 배경색과 라벨처럼 두 가지 이상의 중복 표식으로 보이게 하라고 권한다 (G7). 퀀터스는 공개 실적 집계에서 모의계좌를 뺀다 (Q4).
- 정리: 모드는 설정 항목이 아니라 별도의 작업 공간으로 다룬다. 실전 전환은 토글이 아니라 별도 절차(점검표, 계좌 끝자리 확인)로 한다. 모의 결과 화면에는 모의 체결의 한계(Alpaca 사례: 슬리피지·시장 충격 미반영)를 적는다.

### 3.3 위험 알림
- 관찰: 한국투자증권(위험 패턴에 하루 1~2회 팝업), 키움(강제 중지 시 비상 SMS), QuantConnect(실행 오류 시 이메일), TradingView(알림 만료), Knight Capital(경고 이메일 97통이 무시됨), FCA(푸시 알림만으로 거래 증가).
- 정리: 긴급·중요·정보로 등급을 나누고 등급마다 채널, 빈도, 확인 방식을 다르게 한다. 긴급은 화면 고정 배너와 외부 채널로 보내고, 사용자가 확인할 때까지 남긴다. 같은 원인에서 나온 알림은 한 건으로 묶는다.

### 3.4 긴급 정지
- 관찰: QuantConnect Stop/Liquidate, Cryptohopper 패닉, uTrade 전체 중지/전체 일시정지, Upstox(미체결 취소, 신규 차단, 12시간 냉각), Kraken 데드맨 스위치, Bitsgap(결과형 라벨), 3Commas(정지 방식 선택), 키움(재접속 후 수동 전환).
- 정리: 세 단계(일시정지/정지/전량 청산)를 결과형 라벨로 늘 같은 자리에 둔다. 청산만 2단계 확인과 예상 결과 표시를 거친다. 실행 결과를 항목별로 보고하고(취소된 주문 n건, 실패 n건), 재개는 점검표를 거친다. 엔진의 하트비트가 끊기면 자동으로 신규 주문을 막는다.

### 3.5 주문 승인
- 관찰: 키움(수동은 확인창, 자동은 별도 동의), TradersPost(Auto Submit 해제 시 사람이 처리), 퀀터스(사용자 확인 대기), ai-hedge-fund(실행 전 정확한 결정 표시), Robinhood(검토 후 제스처 제출), IBKR(전송 직전 한도 경고). NN/g는 확인창을 남발하면 습관적으로 누르게 되고, 버튼은 예/아니요가 아니라 결과로 이름 붙이며, 위험한 작업에는 기본 선택을 두지 말라고 한다 (G6).
- 정리: 승인 카드 한 장에 무엇을(종목·방향·수량·금액·주문 유형·가격), 왜(근거 세 줄, 위원회 찬반), 위험(한도 점검 결과), 언제까지(만료)를 담는다. 승인 시점에 가격을 다시 검증한다. 일괄 승인은 좁게 허용한다. 승인 피로를 줄이려면 "한도 안에서는 자동" 단계를 주되 기본값으로 두지 않는다.

### 3.6 실행 로그와 판단 근거
- 관찰: Option Alpha(필터 탈락 사유와 당시 값), QuantConnect(주문 이벤트 상세, 로그 검색과 내려받기), TradingView(알림 로그), 키움(감시내역, 자동주문내역), ai-hedge-fund(해시 원장).

### 3.10 신뢰를 주는 장치
1. 가정과 데이터 출처, 기준 시각을 함께 적는다 (A3, TV1, QC1).
2. 공개 숫자의 집계 기준을 밝힌다 (Q4).
3. 자산이 어디 있고 앱이 무엇을 할 수 있는지(주문만, 출금 불가) 적는다 (Q3, A5).
4. 근거의 출처를 밝힌다(뉴스·리포트·기술적 데이터) (R3, T6).
5. 하지 않은 결정과 그 이유도 남긴다 (A6, A7).
6. 고칠 수 없는 기록과 내보내기를 준다 (G2, QC1).
7. 벤치마크와 바이앤홀드로 비교 기준을 준다 (TV1, QC1).
8. 정확도와 한계를 알린다 (G4, G5).
9. 재현할 수 있게 한다(설정 버전, 복제) (QC1).
10. 오류가 나면 바로 알리고 대응 경로를 준다 (QC2, K4).

## 4. 우리 앱 설계 원칙 (17개)

각 원칙은 "규칙"과 "근거"로 적는다. 수치는 시작값 제안이며 운영 데이터로 조정한다.

### P1. 관제의 1순위는 "개입이 필요한가"다
- 규칙: 모든 화면 상단에 상태 바(엔진, 모드, 세션, 증권사 연결과 토큰, 시세 수신 시각, 승인 대기 수, 일일 손실 한도 사용률)를 고정한다. 대시보드 첫 줄은 미확인 경고와 승인 대기이고, 손익은 그다음이며 손익도 "한도 대비"로 보여준다(예: 오늘 −32만원, 일일 손실 한도 100만원 중 32%).
- 근거: 키움 감시 상태 (K3, K4), QuantConnect 통계 띠와 라이브 대시보드 (QC2), 퀀터스 연결 상태 (Q3), Knight Capital (X3).

### P2. 모의와 실전은 다른 공간으로 다룬다
- 규칙: 환경마다 키, 계좌, 기록, 성과를 따로 둔다. 표식은 두 가지 이상 겹친다(상단 띠 색과 라벨, 주문 버튼 문구에 "실전"). 실전 전환은 별도 절차로 하고, 같은 화면에서 모드를 토글하지 않는다.
- 근거: Alpaca·KIS·키움의 환경 분리 (A4, B9, K7), NN/g 모드 (G7), 퀀터스 집계 기준 (Q4).

### P3. 자동화는 단계로 열고, 기본값은 승인이다
- 규칙: 전략마다 단계를 고른다. 0단계 알림만, 1단계 모든 주문 승인, 2단계 한도 안 자동·한도 밖 승인, 3단계 완전 자동(사후 보고). 새 전략은 1단계로 시작하고, 단계를 올릴 때는 모의 운용 기록과 점검표를 보여준다.
- 근거: 키움 수동/자동과 별도 동의 (K3), TradersPost Auto Submit (A14), 퀀터스 사용자 확인 대기 (Q3), ai-hedge-fund 승인 단계 (G2).

### P4. 승인 카드는 무엇을·왜·위험·기한을 한 장에 담는다
- 규칙: 카드에 종목, 방향, 수량, 예상 금액, 주문 유형, 가격(현재가 대비 괴리 %와 호가 수), 근거 세 줄, 위원회 찬반 요약, 점검 결과, 제안 시각과 만료까지 남은 시간을 담는다. 버튼은 결과로 이름 붙인다(예: "매수 승인 · 10주 · 약 72만원"). 만료되면 자동 거절하고 기록한다. 승인하는 순간 가격을 다시 확인해 허용 괴리를 넘으면 다시 묻는다.
- 근거: 키움(조건 만족 후 가격 재조회로 생기는 차이 경고) (K3), IBKR 가격 괴리 경고 (A17), NN/g 결과형 버튼 (G6).

### P5. 주문 전 점검은 "경고"와 "차단"을 나누고, 설정값은 범위를 검증한다
- 규칙: 차단(넘으면 주문하지 않음)은 일일 손실 한도, 1회 최대 주문 금액, 종목당 최대 비중, 일일 최대 주문 수, 경보·정지 종목, 허용 세션 밖 주문이다. 경고(확인 후 진행)는 가격 괴리, 평소보다 큰 주문, 얇은 호가다. 모든 설정값은 단위와 범위를 검사하고, 오늘 가격 기준 금액과 가격으로 바꿔 미리 보여주며, 누가 언제 무엇을 바꿨는지 남긴다.
- 근거: IBKR 주의 설정 (A17), Option Alpha 안전장치 (A8), 키움 조건요약과 호가 보정 (K3), 한맥투자증권 사고 (X4).

### P6. 정지 버튼은 결과로 이름 짓고 늘 같은 자리에 둔다
- 규칙: 일시정지(신규 주문 중단, 미체결·보유 유지), 정지(신규 중단과 미체결 전부 취소, 보유 유지), 전량 청산 후 정지(장 상태에 따른 주문 방식 안내)를 나눈다. 범위는 전체, 전략별, 종목별이다. 일시정지는 바로 실행하고 되돌릴 수 있게, 정지는 한 번 확인, 청산은 두 단계 확인과 예상 결과(대상 종목 수, 추정 금액, 시간외 처리 방식)를 보여준다. 실행 결과는 항목별 성공·실패로 보고하고, 실패하면 증권사 앱에서 직접 처리하는 방법을 알려준다.
- 근거: QuantConnect (QC3), Cryptohopper (A10), uTrade (A11), Upstox (A16), Bitsgap·Pionex (A12, A13), 3Commas (A1).

### P7. 끊기거나 다시 켜질 때는 안전한 쪽으로 간다
- 규칙: 엔진 하트비트가 끊기거나, 시세가 정해진 시간 이상 늦거나, 토큰이 만료되면 신규 주문을 자동으로 막는다(데드맨 스위치). 재시작·재접속 뒤에는 승인 모드로 돌아가고, 사용자가 점검표(바뀐 시장 상황, 미체결, 한도)를 확인해야 자동으로 재개한다.
- 근거: 키움 재접속 후 수동 전환 (K3), Kraken (A15), Bitsgap 재시작 전 점검 (A12).

### P8. 결정 로그에는 "한 것"과 "안 한 것"을 모두 남긴다
- 규칙: 사슬 ID로 신호, 점검, 결정(실행/보류/탈락), 승인·거절·만료, 주문 상태 변화, 설정 변경, 모드 전환을 묶는다. 각 항목에 입력값, 규칙 결과, 데이터 시각을 남긴다. 기록은 고칠 수 없게(해시 연결) 저장하고 CSV로 내보낸다.
- 근거: Option Alpha (A6, A7, A9), QuantConnect 로그와 주문 이벤트 (QC1, QC2), ai-hedge-fund 원장 (G2), TradingView 알림 로그 (TV7).

### P9. 판단 근거는 찬반을 나란히, 데이터 시점과 함께 보여준다
- 규칙: 결론 카드, 규칙 체크리스트(충족·미충족과 실제 값), 위원별 의견(관점, 판단, 확신, 핵심 근거, 사용한 데이터의 시각), 반대 의견, "무엇이 바뀌면 판단이 바뀌나"를 보여준다. 의견을 합치는 방식(다수결, 가중, 리스크 위원 거부권)을 공개한다. 종합 판단이 위원 평균과 다를 수 있으면 그 이유를 적는다.
- 근거: TradingAgents (G1), Danelfin (G3), Microsoft 가이드라인 11번과 "만약" 설명 (G4), Robinhood Digests의 근거 출처 (R3).

### P10. 확신은 보정해서 보여주고, 실적으로 검증받는다
- 규칙: 소수점 확률 대신 3~5단계 등급과 근거의 일치도를 쓴다. 위원회와 전략의 과거 판단 적중률, 평균 손익, 표본 수를 같은 화면에서 볼 수 있게 한다. 데이터가 부족하거나 이견이 크면 "판단 보류"를 정상 결과로 낸다.
- 근거: Microsoft 가이드라인 2번 (G4), Google PAIR 신뢰 보정 (G5), Danelfin 하위 점수 (G3).

### P11. 백테스트는 가정이 먼저 보이고, 손실이 수익과 같은 크기로 보인다
- 규칙: 가정 요약 띠, 비용 기본 포함, 벤치마크와 바이앤홀드 비교, 자산곡선과 낙폭을 같은 시간축에, 학습/검증 구간 분리, 비용·파라미터 민감도, 재현 정보를 둔다. 거래 수가 적으면 승률 옆에 표본 수 경고를 붙인다.
- 근거: Composer (A3), TradingView (TV1), QuantConnect (QC1), 퀀터스 (Q3), Option Alpha 필터 로그 (A7).

### P12. 성과의 출처를 섞지 않는다
- 규칙: 모든 손익과 수익률 숫자에 출처 라벨(백테스트/모의/실전)과 기간을 붙인다. 실전 성과에 모의 성과를 더하지 않는다. 실전 곡선 위에 같은 기간 백테스트(기대) 곡선을 겹쳐 차이를 보여준다.
- 근거: 퀀터스 집계 기준 (Q4), QuantConnect 라이브 차트 (QC2), Alpaca 모의 체결 한계 (A4).

### P13. 알림은 적게, 행동할 수 있게, 확인될 때까지 보낸다
- 규칙: 긴급(엔진 오류, 연결 끊김, 한도 도달로 정지, 주문 거부 연속, 긴급 정지 실행)은 화면 고정 배너와 외부 채널로 보내고 확인할 때까지 남긴다. 중요(승인 요청, 체결, 감시 조건 도달)는 앱 알림, 정보(일일 요약)는 묶어서 보낸다. 같은 원인은 한 건으로 묶고, 방해 금지 시간에도 긴급은 통과시킨다. 마케팅성 알림과 수익 자랑형 알림은 없다.
- 근거: 한국투자증권 빈도 제한 (B1), 키움 비상 SMS (K4), FCA 푸시 실험 (X1), Knight Capital (X3).

### P14. 한국 표기 관례를 지키되 가격 색과 위험 색을 분리한다
- 규칙: 토큰 예시로 `price-up`(빨강), `price-down`(파랑), `price-flat`(회색)을 두고, `status-danger`, `status-warning`, `status-success`, `mode-live`, `mode-paper`는 따로 정의한다. 위험 표시는 아이콘, 문구, 형태(배너·테두리)를 반드시 함께 쓴다. 가격에는 ▲▼와 부호를 붙여 색을 못 구분해도 읽히게 한다. 실제 색 값은 디자인 시스템 작업에서 대비를 검증해 정한다.
- 근거: 2.1절 관례, NN/g (G7), 색 단독 금지 접근성 원칙.

### P15. 시장 구조를 화면에 드러낸다
- 규칙: 거래소(KRX/NXT/SOR), 현재 세션, 호가단위 자동 보정과 보정 방향, VI·시장경보·매매정지 배지, 세션별로 가능한 주문 유형을 보여준다. 전략 설정에서 허용 세션과 거래소를 고르게 한다.
- 근거: 키움 거래소 선택과 호가 보정 (K3, K4), 2026 KRX 애프터마켓과 NXT·SOR (M1, M2), 시장경보 (M4).

### P16. 쉬운 말과 즐거운 연출로 위험을 가리지 않는다
- 규칙: 툴팁과 단계적 설명은 쓰되 위험 용어는 정식 명칭을 함께 적는다. 게임 요소, 랭킹, 수익 연출은 두지 않는다. 위원회 의견은 "근거 정리"의 말투로 쓰고 개인화된 매수 권유 문구는 피한다. 다른 사용자에게 서비스로 제공한다면 투자권유·유사투자자문 해당 여부를 법률 검토한다.
- 근거: 토스 원칙 (T5)과 비판 사례 (T8, T9), FCA (X1, X2), Robinhood (R1, R2), 국내 투자권유 논의 (B2).

### P17. 연결, 권한, 자산 위치를 투명하게 보여준다
- 규칙: 연결 카드에 환경, 계좌(끝 4자리), 권한(시세·조회·주문, 출금 불가), 토큰 만료 시각, IP 등록 상태, 마지막 성공 호출을 적는다. 키는 저장 즉시 가리고, 다시 볼 수 없다고 알리며, 폐기·재발급의 결과(가동 중 전략이 멈춘다)를 확인받는다. "자산은 내 증권 계좌에 있고, 앱은 주문만 전달한다"를 적는다.
- 근거: Alpaca 키 보안 (A5), 키움 REST(IP 등록, 키 1회 다운로드, 오류 코드) (K6, K7), KIS 환경 분리 (B9), 퀀터스 자산 보관 고지 (Q3), 3Commas 사고 (A2).

## 5. 화면별 권장 구성

### 5.0 공통 골격
- 상단 상태 바(높이 40~48px, 모든 화면 고정): `[실전/모의 배지] [엔진: 가동 중 · 전략 3개] [정규장 10:42:13 · 마감까지 4시간 48분] [키움 연결됨 · 토큰 21시간] [시세 0.3초 전] [승인 대기 2] [알림] [긴급 정지 ▾]`
- 모드 표식: 실전은 상단 띠 전체에 가격 빨강·파랑과 다른 고유 색과 "실전" 라벨, 주문 버튼 문구에도 "실전". 모의는 배경 패턴이나 워터마크와 "모의" 라벨 `[추론]`.
- 왼쪽 내비게이션: 관제, 종목 발굴, 포트폴리오, 백테스트, 자동매매 설정, 설정(증권사 연결).
- 오른쪽 사이드 패널(접을 수 있음): 승인 대기함, 보유·관심, 최근 이벤트. 토스증권 PC의 상시 사이드 패널을 참고한다 (T1, T2).
- 위젯 연동: 종목을 고르면 차트, 호가, 판단 패널이 함께 바뀐다. Robinhood Legend의 색 그룹 연동을 참고한다 (R5).
- 확인 대화상자 3등급: 정보(대화상자 없이 토스트), 주의(한 번 확인, 결과형 버튼), 위험(두 단계 또는 값 입력, 기본 포커스 없음). Enter 키로 실전 주문을 내지 않는다 (K3, G6).
- 보기 밀도: 기본 보기와 고밀도 보기를 둔다. 숙련자는 명령 팔레트로 종목과 화면을 바로 찾는다(HTS 화면 번호 문화의 대체) `[추론]`.

### 5.1 자동매매 관제 대시보드

### 5.3 종목 상세: 차트 + 판단 근거 + 투자위원회
- 헤더: 종목명, 코드, 시장, 거래소, 현재가, ▲/▼ 등락폭과 등락률, 거래대금, 세션, 경보·VI 배지, 데이터 시각, "전략 A가 관리 중" 표식.
- 왼쪽(넓게): 차트. 봉, 거래량, 보조지표에 우리 전략의 신호·체결 표식, 감시 가격선(손절·익절·트레일링, 감시 중은 실선·중지는 회색 점선), 평균 매입가 선을 겹친다. 멀티 차트(2~4개)는 옵션이다 (K3, T3).
- 오른쪽(고정 폭 판단 패널):
  1. 결론 카드: 현재 판단(매수 검토/보유/축소 검토/관망/판단 보류), 확신 등급, 판단 시각과 다음 재평가 시각, 자동매매에서의 의미(예: "10:45에 승인 요청 예정").
  2. 규칙 체크리스트: 전략의 진입·청산 조건마다 충족 여부, 현재 값, 기준 값.
  3. 위원회: 위원마다 한 줄(관점, 판단, 확신, 핵심 근거). 찬반 분포는 개수와 막대로 함께 보여준다. 리스크 위원 의견은 따로 강조하고, 거부권이 있으면 그렇다고 적는다. "토론 요약 펼치기"에 강세·약세 주장, 반박, 진행자 결론을 둔다 (G1).
  4. 판단을 바꿀 조건: 예) 종가가 20일선 아래로 마감하면 "축소 검토"로 바뀐다 (G4).
  5. 근거 출처: 뉴스, 공시, 재무, 수급 데이터의 시각과 링크. AI 요약에는 AI 표식과 호재/악재 분류를 붙인다 (T6, R3).
  6. 위원회 설명과 실적: 각 위원이 무엇을 보는지, 과거 판단 적중률과 표본 수 (G4, G5).
- 아래 탭: 호가(10단, 자동 주문·감시 가격 표식), 체결, 뉴스·공시, 재무, 투자자별 수급, 내 거래 이력(매매일지 연결).
- 수동 주문: 접힌 패널. 자동매매가 관리하는 종목에 수동 주문하면 전략과 충돌한다고 경고하고 처리 방식(전략에서 빼기/한도 계산에 넣기)을 고르게 한다 (QC3, A8).

### 5.4 자동매매 설정·주문 승인

설정 단계(마법사, 끝나면 요약 화면에서 항목별로 고친다)
1. 전략 선택: 최근 백테스트 요약과 검증 구간 성과 링크.
2. 대상: 유니버스·종목, 경보 종목 제외, 허용 거래소·세션.
3. 자금: 전략별 할당 금액(필수), 현금 여유분.
4. 위험 한도: 1회 최대 주문 금액·수량, 종목당 최대 비중, 일일 최대 손실(도달 시 동작: 일시정지/정지/청산), 일일 최대 주문 수, 연속 손실 n회 시 정지, 허용 가격 괴리 %.
5. 주문 방식: 주문 유형, 가격 기준(현재가/신호 시점 가격), 호가단위 보정, 분할 집행, 미체결 처리(n분 뒤 취소 또는 정정).
6. 청산 규칙: 손절·익절·트레일링, 오늘 가격으로 환산한 실제 가격 표시.
7. 자동화 단계(0~3)와 승인 만료 시간.
8. 검토: 모든 설정을 오늘 가격 기준 금액과 가격으로 바꾼 요약, 경고 목록. 기본 버튼은 "모의로 시작"이고, 실전은 별도 버튼과 별도 확인을 거친다.

- 가동 중 변경: 바뀌기 전과 후를 비교해 보여주고, 적용 시점(즉시/다음 신호부터)을 고르며, 일부 항목은 일시정지 뒤에만 바꿀 수 있고, 모든 변경을 기록한다 (A1).
- 근거: 키움 (K3, K4), Option Alpha (A8), IBKR (A17), Bitsgap (A12).

승인함
- 카드: 전략 이름과 모드, 종목과 방향, 수량과 예상 금액, 주문 유형과 가격(현재가 대비 괴리 %·호가 수), 근거 세 줄, 위원회 찬반 요약, 점검 결과(통과/경고 항목), 제안 시각과 만료까지 남은 시간.
- 버튼: "매수 승인 · 10주 · 약 72만원"(결과형), "거절"(사유는 선택), "수정 후 승인"(수량·가격만).
- 규칙: 만료되면 자동 거절하고 기록한다. 승인 시 가격을 다시 확인한다. 일괄 승인은 같은 전략, 같은 방향, 한도 안의 건만 허용한다. 실전 승인에는 Enter 단축키를 쓰지 않고, 키보드 사용자는 포커스를 옮겨 명시적인 버튼을 누른다.
- 근거: 퀀터스 (Q3), TradersPost (A14), NN/g (G6), Robinhood 검토 후 제출과 접근성 문제 (R6, R8).

### 5.5 포트폴리오: 보유·주문·매매일지
- 요약 띠: 총 평가자산, 평가손익, 기간 실현손익, 예수금, 출처 라벨(실전/모의).
- 보유 탭: 종목, 수량, 평균 매입가, 현재가, 평가금액, 평가손익(금액·%), 비중, 관리 주체(전략 이름/수동), 감시 조건과 현재가까지 거리, 거래소, 합계 행.
- 주문 탭: 상태 필터(승인 대기, 전송 중, 미체결, 부분 체결, 체결, 취소, 거부, 만료)와 사유, 출처 태그(자동/승인/수동), 주문 이벤트 타임라인 펼치기, 선택 취소와 전체 미체결 취소(확인).
- 매매일지 탭: 진입부터 청산까지 한 거래 단위. 손익, 보유 기간, 수수료와 세금, 진입 당시 근거와 위원회 의견 스냅샷, 청산 사유(규칙 이름), 메모와 태그, CSV 내보내기.
- 손익 분석: 월별 달력(빨강/파랑과 숫자), 전략별·종목별 기여, 비용 포함 여부 표기.
- 근거: QuantConnect 주문·거래 탭 (QC1, QC2), 키움 감시내역 (K4), Option Alpha 수동 개입 처리 (A8).

### 5.6 백테스트
- 입력: 전략, 기간(프리셋과 직접 입력), 유니버스(과거 시점 구성, 상장폐지 종목 포함 여부), 초기 자금, 비용(수수료·세금·슬리피지, 기본값은 0이 아님), 리밸런싱 주기, 벤치마크(코스피/코스닥/바이앤홀드), 학습/검증 분할. 실행 진행률과 예상 시간을 보여준다 (Q1).
- 결과 머리: 가정 요약 띠(한 줄, 펼치면 전체), "가상 결과" 표식, 재현 정보(설정 버전, 데이터 기준일, 실행 시각).
- 지표 타일(벤치마크 대비 차이를 함께): CAGR, 누적수익률, MDD(기간과 회복일), 변동성, 샤프, 소르티노, 승률, 손익비, 거래 수, 회전율.
- 차트: 위에 자산곡선(로그 축 옵션, 전략·벤치마크·바이앤홀드), 아래에 같은 시간축의 낙폭 차트, 학습/검증 구간 음영, 월별 수익률 히트맵, 연도별 막대, 손익 분포, 연속 승패.
- 검증: 구간별 지표 표, 비용 민감도(슬리피지 세 단계), 파라미터 민감도 히트맵, 시장 국면별 성과.
- 거래 목록과 필터 탈락 목록(날짜, 사유, 당시 값) (A7).
- 비교: 두 결과를 나란히 보되, 가정이 같을 때만 비교할 수 있다고 표시한다.
- 다음 행동: "모의로 운용 시작" 버튼. 실전 운용 중에는 실전 곡선과 백테스트 곡선을 겹쳐 본다 (QC2).
- 하지 말 것: 가장 좋은 구간을 자동으로 고르기, 비용 0을 기본값으로 두기, 거래 수가 적은데 높은 승률을 강조하기.

### 5.7 증권사 연결 설정
- 모의와 실전 두 구역을 물리적으로 나눈다(다른 배경, 다른 카드). 각 구역에 증권사별 연결 카드를 둔다.
- 카드: 증권사, 환경, 계좌(끝 4자리), 상태(연결됨/토큰 만료 임박/만료/IP 불일치/인증 실패/장기 미사용 해지 위험), 토큰 만료 시각과 자동 갱신 여부, 마지막 성공 호출 시각, 지원 범위(예: 키움 모의 도메인은 KRX만 지원한다는 안내, K6), 권한 요약(시세·조회·주문, 출금 불가).
- 키 등록: 앱키와 시크릿 입력(붙여넣기 허용), 저장하자마자 가리기, 다시 볼 수 없다는 안내, 연결 테스트(잔고 조회로 확인). 실패하면 오류 코드별 해결 방법을 보여준다. 예: 키움은 IP 불일치 8010, 실전 키로 모의 도메인 접속 8031, 토큰 만료 8005 `[2차]` (K7).
- IP 등록 도우미: 현재 서버의 공인 IP를 보여주고 복사하게 하며, 등록 위치를 안내한다. 키움은 계좌 App Key 관리에서 IP를 최대 10개 등록한다 `[2차]` (K7).
- 환경 분리: 모의·실전 키와 토큰 캐시를 따로 저장하고, 실행 중에 모드를 바꾸지 않는다 (B9).
- 폐기와 재발급: 결과(가동 중 전략이 멈춤)를 설명하고 확인받는다. 유출이 의심되면 폐기 → 노출 기간 주문·체결 점검 → 재발급 순서로 안내한다 (A5).
- 장애 대비: 앱이 응답하지 않을 때 증권사 HTS·MTS에서 미체결을 취소하는 방법, 비상 연락 채널 등록 (K4).
- 고지 문구: 자산은 내 증권 계좌에 있고 앱은 주문만 전달한다 (Q3).

### 5.8 첫 실행 흐름(온보딩)
1. 앱이 할 수 있는 일과 한계(얼마나 잘하는지, 무엇을 못 하는지) 설명 (G4).
2. 모의 계좌 연결.
3. 위험 한도 직접 입력(기본값은 제시하되 사용자가 확정).
4. 전략 선택과 백테스트 결과 확인.
5. 모의 운용(권장 기간 표시).
6. 실전 전환 점검표: 모의 기간 성과와 기대 대비 차이, 알림 수신 확인, 비상 연락처, 긴급 정지 위치 확인 (K4).
7. 실전 첫 단계는 승인 모드와 작은 한도.
- 단계마다 남은 단계를 보여주고, 건너뛸 수 있는지 분명히 적는다.

## 6. 열린 질문과 다음 단계
- 위원회 의견을 다른 사용자에게 제공할 경우 투자권유·유사투자자문 해당 여부를 법률 검토한다 (B2, Q1).
- 실전 모드 색과 위험 색 토큰을 가격 빨강·파랑과 구분해 확정한다. 디자인 시스템 작업에서 대비를 검증한다.
- 승인 만료 시간과 가격 재검증 허용 괴리의 기본값을 전략 특성별로 정한다.
- 연결할 증권사마다 모의 지원 범위, 토큰 수명, 호출 한도, 장기 미사용 해지 규정을 공식 문서로 다시 확인한 뒤 연결 화면 문구를 확정한다.
- 사용성 테스트 과제: 긴급 정지를 찾는 데 걸리는 시간, 현재 모드를 맞히는 비율, 승인 카드만 보고 주문 내용을 설명할 수 있는지.

## 7. 용어 메모
- PSR: 확률적 샤프 비율. 관측된 샤프 비율과 표본 길이, 수익률 분포 모양을 고려해 실제 샤프 비율이 기준값(보통 0)보다 클 확률을 추정한 값. QuantConnect가 기본 통계로 보여준다 (QC1).
- MDD: 최대 낙폭. 고점에서 저점까지 가장 크게 떨어진 비율.
- 바이앤홀드: 같은 대상을 처음에 사서 끝까지 들고 있는 비교 기준.
- 데드맨 스위치: 정해진 시간 안에 "살아 있음" 신호가 없으면 자동으로 주문을 취소하거나 멈추는 장치 (A15).
- SOR: 여러 거래소 중 유리한 곳으로 주문을 보내는 증권사의 자동 주문 전송 시스템 (M1).
