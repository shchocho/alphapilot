# 24시간 서버 운영 점검 (2026-11-17)

외부 리눅스 서버 한 대에서 사람이 지켜보지 않아도 거래일마다 장 마감 뒤 일봉 갱신 → 거래일 처리 → 점검이 돌아가는 것을 기준으로 DB와 설정을 다시 봤다. 배포 방법은 [deploy.md](deploy.md)에 있다.

## 하루 흐름 (서버 시각 KST)

| 시각 | 하는 일 | 실패하면 |
|---|---|---|
| 거래일 15:45 이후 1분마다 확인 | 일봉 갱신(네이버 금융) | 오늘 봉이 없거나 갱신이 실패하면 15분마다 다시 시도. 23:00까지 못 받으면 원장에 오류를 남기고 그날 자동 처리를 멈춘다 |
| 갱신 직후 | 시뮬레이션이 최신을 따라가던 중이면 밀린 거래일 처리(최대 5일) | 과거 구간을 재생하던 중이면 자동으로 진행하지 않는다. 5일보다 많이 밀렸으면 원장에 안내를 남긴다 |
| 처리 직후 | DB 점검: 백업, 만료 세션·오래된 로그인 기록 정리, 무결성 검사, WAL 정리 | 점검이 실패해도 매매는 막지 않는다. 원장에 오류로 남긴다 |
| 늘 | `/api/health`가 DB 접근과 스케줄러 루프를 확인 | 비정상이면 503. Docker 상태 검사가 unhealthy로 표시한다 |

## 찾은 문제와 고친 것

| # | 문제 | 위험 | 고친 것 |
|---|---|---|---|
| 1 | 스키마 버전 관리가 없었다. 시작할 때 `create_all`만 했고 `SCHEMA_VERSION`은 쓰이지 않았다 | 표를 바꾸는 업데이트(예: 로그인 아이디 추가)를 올리면 운영 DB의 기존 표는 바뀌지 않아 오류가 나거나 조용히 어긋난다 | `app/store/migrate.py`: `PRAGMA user_version`으로 버전을 적고, 올릴 버전이 있으면 먼저 `backups/`에 사본을 남긴 뒤 차례로 올린다. 실패하면 사본 경로를 알리고 멈춘다. DB가 코드보다 새 버전이면 시작하지 않는다. 지금 DB는 v1로 잡힌다(데이터는 그대로) |
| 2 | "엔진은 하나만"을 문서로만 지켰다 | 같은 데이터로 프로세스·컨테이너가 둘 뜨면 스케줄러가 둘이 돼 같은 주문이 두 번 나갈 수 있다 | `app/store/lock.py`: 데이터 폴더의 `engine.lock`을 운영체제 잠금으로 잡는다. 둘째 프로세스는 시작하지 않는다. 프로세스가 죽으면 잠금은 저절로 풀린다 |
| 3 | 갱신 전에 "오늘 했음"을 먼저 적었다 | 네이버가 잠깐 안 되거나 오늘 봉이 늦게 올라오면 그날 처리를 통째로 잃는다 | 오늘 봉이 실제로 들어온 뒤에만 "했음"으로 적고, 그 전에는 15분마다 다시 시도한다 |
| 4 | 시뮬레이션이 정확히 하루 밀렸을 때만 자동 진행했다 | 서버가 하루 넘게 멈췄다 켜지면 이틀 이상 밀려 영영 자동으로 진행하지 않는다 | 시뮬레이션이 최신까지 따라온 날을 기록해 두고, 그날에서 멈춘 채 밀린 경우(=따라가던 중)에는 최대 5거래일을 차례로 처리한다. 과거 재생과는 구분한다 |
| 5 | "오늘 했음"을 메모리에만 들고 있었다 | 재시작할 때마다 같은 날을 다시 갱신하고 원장에 같은 줄이 쌓인다 | DB(KV)에 적는다 |
| 6 | 끌 때 진행 중인 처리를 바로 끊었다 | 업데이트·재시작 순간이 처리 중이면 체결만 반영되고 장후 심의·주문 계획이 없는 날이 생긴다 | 끌 때 진행 중인 틱을 45초까지 기다린다. `docker-compose.yml`의 `stop_grace_period`를 60초로 |
| 7 | 저장된 설정이 지금 코드와 안 맞으면(없어진 모델 이름, 좁아진 범위) 설정을 읽는 모든 요청이 실패했다 | 업데이트 한 번으로 엔진·화면이 모두 멈춘다 | 맞지 않는 필드만 기본값으로 되돌리고, 시작할 때 무엇을 되돌렸는지 원장에 남긴다 |
| 8 | `/api/health`가 늘 `ok`였다 | DB가 잠기거나 스케줄러가 멈춰도 상태 검사가 정상으로 본다 | DB 접근과 스케줄러 루프(마지막 틱, 걸린 틱, 죽은 루프)를 본다. 비정상이면 503. 로그인 없이 열리는 곳이라 상태 이름만 내보낸다 |
| 9 | 로그 설정이 없었다(앱 로그에 시각이 없고 INFO는 안 나옴). Docker 로그는 크기 제한이 없었다 | 문제를 나중에 추적할 수 없고, 오래 돌면 디스크가 찬다 | 시각을 붙여 표준 출력으로 내보낸다(`AP_LOG_LEVEL`). 컨테이너 로그는 10MB×5개까지 |
| 10 | 운영 설정이 빠진 것을 첫 요청 때에야 알았다 | 서버는 떠 있는데 로그인이 안 되는 상태가 된다 | 시작하기 전에 점검하고, 빠진 것이 있으면 무엇을 고칠지 알리고 멈춘다(짧은 `AP_SECRET_KEY`, 도메인 없는 `AP_ALLOWED_HOSTS`, 가짜 데이터, 실전 키 없는 실전 잠금 해제) |
| 11 | 백업은 서버의 cron에 걸어야만 됐다. 만료된 세션과 로그인 시도 기록은 지우지 않았다. 무결성 검사가 없었다 | cron을 빠뜨리면 백업이 없다. 기록이 끝없이 쌓인다 | 하루 한 번 데이터 폴더 `backups/`에 자동 백업(`AP_BACKUP_KEEP`, 기본 14개). 만료 세션·30일 지난 로그인 기록 정리, `quick_check`, WAL 정리 |
| 12 | Docker 이미지가 `uv:latest`를 받았다 | 같은 코드라도 빌드할 때마다 결과가 달라질 수 있다 | `uv:0.13.6`으로 고정 |

## 바꾸지 않은 것

- **SQLite.** 한 사람이 쓰고 쓰는 프로세스가 하나라 충분하다(WAL, `busy_timeout` 5초). 여러 사용자가 각자 엔진을 돌리거나 서버를 여러 대로 늘릴 때 Postgres로 옮긴다.
- **원장과 감사 기록은 지우지 않는다.** 원장은 해시 사슬이라 지우면 검증이 깨진다.
- **비밀값은 `.env`(서버 환경변수)에 둔다.** 예외로 증권사 키는 설정 화면에서 넣을 수 있고, 이때는 `AP_SECRET_KEY`로 암호화해 DB에 둔다(2026-11-18, 스키마 v2). 화면으로는 어느 쪽 키도 내려보내지 않는다.

## 남은 일 (중요한 순서)

1. **알림.** 오류·재시작·데이터 실패가 지금은 원장과 로그에만 남는다. 사람이 안 보는 서버라 텔레그램 같은 알림이 가장 먼저 필요하다.
2. **바깥 감시.** 업타임 감시 서비스로 `https://<도메인>/api/health`를 1~5분 간격으로 본다. 서버가 통째로 꺼진 것은 서버 안에서 알 수 없다.
3. **서버 밖 백업과 복구 연습.** 자동 백업은 같은 디스크에 있다. `deploy/backup.sh`를 cron에 걸어 다른 곳으로 옮기고, 아래 복구 순서를 한 번 실제로 해 본다.
4. **휴장일 표.** `app/core/clock.py`에는 2026년 확정, 2027년 잠정까지만 있다. 매년 말 KRX 공지로 다음 해를 넣는다. 화면 상태의 `calendar_confirmed_through`로 확인한다.
5. **Docker 빌드를 실제로 돌려 보기.** 이 구성은 아직 실제 서버에서 빌드해 보지 않았다.
6. **키움 주문 실행기를 붙일 때.** 주문을 보내기 전에 DB에 먼저 적고(보낼 주문 목록), 재시작하면 키움의 미체결·체결 내역과 맞춰 본 뒤에 이어 간다. 응답이 애매한 주문은 다시 보내지 않는다.
7. **표를 바꾸는 일**(사용자별 데이터 등)은 마이그레이션으로 한다. 순서는 `app/store/migrate.py` 맨 위에 있다. 로그인 아이디는 v2로 넣었다(2026-11-18).

## 복구 순서

```bash
docker compose stop app
```

```bash
docker compose cp ./backups/alphapilot-daily-YYYYMMDD-HHMMSS.db app:/data/alphapilot.db
```

컨테이너가 멈춰 있으면 `docker compose cp`가 안 될 수 있다. 그때는 볼륨 경로(`docker volume inspect` 결과의 Mountpoint)에 직접 복사하고, 같은 폴더의 `alphapilot.db-wal`, `alphapilot.db-shm`을 지운다.

```bash
docker compose start app
```

다시 켜면 엔진은 승인 대기 상태로 시작한다(재시작 확인). 원장 검증(`/api/ledger/verify`)이 통과하는지 확인한다.
