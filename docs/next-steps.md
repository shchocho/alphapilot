## 다른 PC에서 이어 하기

- 처음이면 `git clone https://github.com/shchocho/alphapilot.git`, 이미 받아 둔 폴더면 `git pull`. 실행 명령은 [README](../README.md)의 "내 PC에서 실행"을 따른다.
- Windows에서는 짧은 경로에 둔다(예: `C:\dev\alphapilot`). 경로가 길면 260자 제한에 걸려 `uv sync`로 만든 가상환경이 깨진다.
- **GitHub에 없는 것:** `.env`, `backend/data/alphapilot.db`(로그인 계정, 시뮬레이션 기록, 시세), `backups/`.
  - 옮기지 않으면 처음 등록부터 다시 하고, 시뮬레이션도 새로 시작한다.
  - 같은 상태로 이어 가려면 DB와 `.env`를 함께 USB 등으로 직접 옮긴다. `AP_SECRET_KEY`가 다르면 인증 앱 등록을 다시 해야 한다.
  - DB에는 비밀번호 해시와 매매 기록이 들어 있으므로 메신저나 공유 링크로 보내지 않는다.

## 키움 연결

- 쓰는 것은 영웅문(HTS)이 아니라 **키움 REST API**(openapi.kiwoom.com)다. 영웅문을 켜 둘 필요가 없고, 모의투자 서버(`mockapi.kiwoom.com`)가 따로 있다. 준비 방법은 [kiwoom-setup.md](kiwoom-setup.md).
- 지금 있는 것: 토큰 발급과 잔고 조회, 유량 제어, 주문 응답 해석. 실제 키움 서버에 붙여 본 적은 없고 주문 실행기는 없다.
- 순서:
  1. 직접 할 일: 모의투자 앱 키 발급, 서버 IP 등록, `.env`에 키 넣기
  2. 연결 확인
  3. 확인 안 된 17개 항목 검증(유량 초과 응답 모양, 정정·취소 규칙, 체결 알림 순서 등)
  4. 주문 실행기: 보내기 전에 DB에 먼저 적고, 결과가 애매하면 다시 보내지 않고 조회로 확인한다. 재시작하면 키움의 미체결·체결 내역과 맞춰 본 뒤 이어 간다
  5. 모의 계좌로 몇 주 돌리기
  6. 실전은 100만원 한도로 시작

## 토스증권 연결

토스증권 Open API는 2026-08-13에 정식 출시됐다(공식 문서로 확인).

- 맞는 점: 국내 지정가·시장가 주문. **시가 단일가 주문(OPG)**이 있어 "다음 날 시가 체결" 방식과 맞고, **조건주문(OCO/OTO)**으로 손절·익절을 증권사 서버에 걸어 둘 수 있다.
- 조심할 점:
  - 모의투자 서버가 없어 처음부터 실계좌로만 시험할 수 있다.
  - 허용 IP를 등록해야 하고, 클라이언트당 유효 토큰은 1개뿐이다.
  - 국내 주식은 소수점 주문이 안 된다.
  - 받은 데이터는 투자자 본인의 매매 목적으로만 쓰고 제3자에게 배포하면 안 된다.
- 방법: 브로커 공통 인터페이스(`backend/app/broker/base.py`) 아래에 토스 어댑터를 하나 더 붙인다. 검증은 키움 모의투자로 하고, 토스는 실전 연결 대안으로 둔다.

## 계정(아이디·비밀번호)

- DB와 로그인은 이미 있다(SQLite, 비밀번호 Argon2id, 인증 앱 코드, 세션, CSRF 방어).
- 사용자 행은 여전히 `id=1` 하나다. 거래·장부도 사용자별로 나뉘지 않는다(B안을 할 때 바꾼다).

**A안 완료(2026-11-18, 브랜치 `feat/login-id`, 스키마 v2):**

- 로그인에 아이디를 더했다. 영문 소문자·숫자 3~32자, 대소문자는 가리지 않는다. 기존 DB의 관리자는 아이디 `admin`이 된다. 아이디가 틀려도 비밀번호·코드가 틀린 것과 같은 오류를 돌려준다.
- 복구 코드 10개: 처음 등록을 마칠 때 한 번만 보여 준다. 로그인 화면에서 6자리 코드 대신 넣으면 한 번 쓰고 없어지고, 그 세션은 5분 동안 재인증된 상태라 바로 새 인증 앱을 연결할 수 있다. 기존 DB에는 복구 코드가 없으니 설정 → 계정에서 만들어 둔다.
- 설정 → 계정: 비밀번호 바꾸기(지금 비밀번호 확인, 다른 기기 로그아웃), 복구 코드 새로 만들기, 인증 앱 다시 연결(새 코드를 확인하기 전까지는 이전 앱이 그대로 쓰인다). 모두 재인증이 필요하다.
- 증권사 키: 설정 → 거래 환경에서 넣는다. `AP_SECRET_KEY`로 암호화해 `broker_keys` 표에 두고, 있으면 `.env` 값보다 먼저 쓴다. 저장·삭제는 재인증이 필요하고, 화면으로는 어디서 온 키인지(db/env)만 내려보낸다.
- 아이디 바꾸기는 넣지 않았다. 바꾸려면 `users` 표의 `username`을 직접 고친다.
- 실전 키를 화면에서만 넣고 `ALLOW_LIVE_TRADING=true`로 운영 서버를 띄우면, 시작 점검이 DB를 보기 전에 "실전 키가 없다"며 멈춘다. 실전으로 갈 때 `.env`에도 넣거나 점검 순서를 바꾼다.

| 안 | 내용 | 규모 |
|---|---|---|
| **A. 혼자 쓰기 + 아이디 추가 (추천)** | 로그인에 아이디를 더하고, 인증 앱 분실용 복구 코드와 비밀번호 변경을 넣는다. 증권사 키는 DB에 암호화해 저장하고 설정 화면에서 재인증한 뒤에만 바꾼다 | 작음 |
| B. 가족·지인 몇 명 | 모든 데이터 표에 사용자 번호를 붙이고, 사용자마다 엔진·장부·증권사 키를 따로 둔다 | 큼 |
| C. 다른 사람 돈을 운용하는 서비스 | 투자일임업 등록이 필요할 가능성이 높고, 키움·토스 모두 데이터를 본인 매매용으로 제한한다. 법률 검토 없이는 권하지 않는다 | 큼 + 법적 위험 |
