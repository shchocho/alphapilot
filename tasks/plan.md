# Implementation Plan: AlphaPilot

기준 명세: `SPEC.md` v0.2 (2026-11-15 승인). 작업 목록: `tasks/todo.md`.

## Overview

유명 기법으로 종목을 찾고, 결정론 좌석 + Claude AI 위원회가 판단하고, 축소 전용 리스크 게이트를 거쳐
가상 계좌(시뮬레이션) 또는 키움 REST로 주문하는 1인용 웹 서비스. 백엔드(FastAPI) → 프론트(React) → 배포 순서로 만든다.

## Architecture Decisions

1. **기능 코어 / 명령 셸 분리.** `engine/core.py`는 DB를 모르는 순수 로직(하루 체결 재현, 장후 사이클)이고,
   `engine/service.py`가 DB·브로커·원장을 붙인다. 백테스트와 시뮬레이션이 **같은 코어**를 돈다(결과 불일치 방지).
2. **하루 단위 `advance(day)`.** ① 대사 → ② 오늘 주문 계획 체결(시가) → ③ 장중(보호 청산·돌파 진입) → ④ 평가·회로차단기 →
   ⑤ 장후 사이클(국면 → 기법 → 좌석 → 위원회 → 게이트 → 내일 계획). 시뮬레이션은 과거 일봉으로 이 순서를 재생하고,
   키움 모드는 스케줄러가 같은 단계를 실제 시각에 실행한다.
3. **특성(feature) 사전 계산.** 종목별 지표를 전 기간에 대해 한 번 계산(모두 과거만 보는 이동 계산)하고 날짜 인덱스로 읽는다.
   백테스트 100종목 × 3년을 60초 안에 돌리기 위함.
4. **환경 3개를 데이터로 분리.** `sim`(가상 계좌) / `mock`(키움 모의) / `live`(키움 실전). 모든 기록에 `env`가 붙고 성과를 섞지 않는다.
5. **AI는 범위 안에서만 고른다.** 규칙이 허용 행동·최대 수량·손절가를 먼저 계산 → AI가 선택(JSON 스키마) → 게이트가 축소·거부.
   AI 실패·거절·시간 초과·예산 초과 = HOLD. 판단 주체 설정: `ai`(기본) / `rules`(백테스트·키 없는 시뮬레이션용, 명시적으로만).
6. **키움 장중 감시는 1차로 REST 폴링.** 보유·감시 종목 수가 적어(≤ 20) 유량 안에서 5~10초 주기로 충분하다.
   WebSocket 실시간(00·04·0B)은 모의 도메인에서 검증한 뒤 붙이는 후속 단계로 둔다(명세 §3.4 갱신).
7. **원장은 해시 연결.** 모든 판단·주문·설정 변경이 `ledger`에 `prev_hash`와 함께 쌓인다. 화면의 "통장정리"가 이 원장을 읽는다.
8. **보안.** Argon2id + TOTP, 서버 저장 세션(토큰 해시), CSRF 이중 제출 + SameSite=Strict, 로그인 속도 제한, 재인증(step-up),
   보안 헤더, 실전 전환 4중 조건. 비밀값은 환경변수에만.
9. **저장소는 SQLite(WAL) + SQLAlchemy 2.** 단일 워커. 스키마는 `create_all`로 시작하고 버전 표로 이후 마이그레이션 여지를 둔다.
10. **프론트.** React 19 + Vite + TS + Tailwind v4, TanStack Query, React Router. 캔들은 Lightweight Charts.
    시각 세계는 "통장정리"(2026-11-15 사용자 선택): 통장 표지색 레일, 인자 숫자, 계획 전용 보라 잉크, 거래번호.

## Dependency Graph

```
core(models, market_rules, clock) ─┬─ data(provider, store, universe) ─ features/indicators ─┬─ techniques ─┐
                                   │                                                          └─ regime ─────┤
                                   ├─ risk(sizing, gate, breakers, exits) ────────────────────────────────────┤
                                   ├─ broker(base, paper, kiwoom) ─────────────────────────────────────────────┤
                                   └─ journal(ledger) ─────────────────────────────────────────────────────────┤
                                                              committee(seats, ai, deliberation) ───────────────┤
                                                                                         engine(core → service → scheduler)
                                                                                         backtest(runner, metrics)
                                                                                         api(auth, routers, SSE) → web → deploy
```

## Phases

1. **기반** — 프로젝트 골격, 도메인 모델, 시장 규칙, 데이터 공급자·캐시·유니버스
2. **판단 재료** — 지표·특성, 기법 8종, 시장 국면
3. **안전장치와 실행** — 리스크, 가상 계좌 체결, 원장, 키움 어댑터
4. **위원회** — 좌석, 규칙 위원회, AI 심의(가짜 클라이언트 테스트)
5. **엔진·백테스트** — 코어, 서비스, 스케줄러, 백테스트
6. **API** — 인증·보안, 라우터, SSE
7. **화면** — 셸·토큰 → 관제 → 발굴·상세 → 위원회·자동매매 → 포트폴리오·백테스트·설정
8. **검증·배포** — 통합 테스트, 브라우저(밝은·어두운·375px), 디자인 리뷰, Docker·문서

## Risks and Mitigations

| 위험 | 영향 | 대응 |
|---|---|---|
| 키움 실 API를 호출해 볼 수 없음(키 없음) | 높음 | 문서 예시 기반 계약 테스트, 설정의 연결 테스트, 미검증 17항목 목록 유지, 기본 환경은 sim |
| AI 호출을 실제로 돌려 보지 못함(비용·키) | 중간 | 가짜 클라이언트로 정상·거절·시간 초과·스키마 위반 테스트. 실제 호출은 사용자가 키를 넣은 뒤 |
| 공개 일봉 경로가 막히거나 바뀜 | 중간 | 공급자 인터페이스 + SQLite 캐시 + 샘플(합성) 공급자로 대체 가능 |
| 백테스트·시뮬레이션 로직 불일치 | 높음 | 같은 `engine/core.py` 사용, 스냅샷 테스트 |
| 기법 임계값이 KRX에서 검증되지 않음 | 중간 | 모든 임계값을 설정으로, 화면에 "검증 안 된 시작값" 표시, 표본 30건 미만 경고 |
| 범위가 커서 화면 완성도 하락 | 중간 | 관제 → 상세 → 승인 순으로 핵심 흐름부터, 화면마다 브라우저 확인 |
